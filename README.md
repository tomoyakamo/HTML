0.1s: 衝撃（トントン）の瞬間的な変化を見たいとき。

縦軸の安定化: suggestedMax: 0.5 を設定し、小さなノイズでグラフが上下に激しく跳ねすぎるのを抑えました。

PSD解析で「0〜100Hz」の範囲を見たいという目標に対して、現在の「60Hz」がどのような状態なのか、専門的な視点から解説しますね。
1. サンプリング60Hzの意味
これは、スマホが1秒間に60回、加速度の値を読み取っていることを意味します。
この数値は非常に重要で、FFT（高速フーリエ変換）やPSD解析における**「解析可能な周波数の上限」**を決定します。
2. 「ナイキスト周波数」の壁
デジタル信号処理には「ナイキストの定理」という絶対的なルールがあります。
> 解析できる周波数の上限 ＝ サンプリング周波数 ÷ 2
> 
現在の設定（60Hz）では、理論上 30Hzまで しか解析できません。
もし100Hzの振動がスマホに伝わっていても、今の設定ではそれを正しく認識できず、「エイリアシング（折り返し雑音）」という現象によって、実際とは違う低い周波数のノイズとしてグラフに現れてしまいます。
3. 0〜100Hzの解析を実現するための課題
目標の「100Hzまで」を解析するには、最低でも 200Hz以上のサンプリングレート が必要になります。
残念ながら、現在のブラウザ（特にiPhoneのSafariや一般的なAndroidの標準設定）では、セキュリティや負荷軽減のために 60Hz〜100Hz程度に制限 されていることが多いのが実情です。
実現するためのアプローチ：
 * AndroidのChromeフラグ: Chromeの高度な設定（chrome://flags）でセンサーの制限を解除できる場合があります。
 * 専用API（Generic Sensor API）の試行: 現在の devicemotion ではなく、LinearAccelerationSensor を使い、明示的に frequency: 200 を要求してみる（端末が対応していれば可能です）。
 * ネイティブアプリ化: ブラウザの制限を回避するため、FlutterやReactNativeなどで簡単なアプリを自作すれば、センサー本来の性能（200〜400Hz程度）を引き出せます。
今後のアドバイス
もし現在の「60Hz（上限30Hz解析）」のままで進める場合、以下のような活用が現実的です。
 * 低周波振動の監視: 新幹線の車体揺れや、大きな構造物の固有振動（数Hz〜20Hz程度）であれば、今のままでも十分に高精度なPSD解析が可能です。
 * 傾向管理: 100Hzまでの正確な値は出せなくても、「普段よりグラフが全体的に盛り上がっている（振動が大きくなっている）」という相対的な変化を捉える用途には使えます。
